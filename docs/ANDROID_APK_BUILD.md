# Android APK 构建流程记录

更新时间：2026-11-05

## 本次问题

原 Android debug APK 工作流把 Godot 项目资源导入、Android Gradle 构建模板安装、APK 导出放在同一个步骤中，缺少独立耗时和日志边界；Godot、导出模板及 Android SDK 每次均重新下载/安装，冷启动成本高。此前构建长时间停留在该合并步骤，无法从步骤状态判断具体瓶颈。

## 优化方案

在独立分支 `ci/optimize-android-apk-export-2026-11-05` 新增优化版工作流，不修改 main，也不取消正在运行的旧构建。

- 固定 Godot 4.7.2、Android API 35、Build Tools 35.0.0、NDK 28.1.13356709、CMake 3.10.2.4988404，避免工具链漂移。
- 缓存 Android SDK、Godot 可执行文件、Godot Android 导出模板、Godot 导入资源和 Gradle 依赖；缓存未命中时自动安装。
- 将资源导入、Android 构建模板安装、APK 导出拆成独立步骤。
- 各阶段独立超时：资源导入 20 分钟、模板安装 10 分钟、APK 导出 45 分钟；保留 90 分钟 job 总超时。
- 每阶段写入独立日志和 UTC 起止时间；无论成功失败都上传诊断日志。
- APK 导出后检查文件非空，输出文件类型、SHA-256 和大小，再上传 14 天可下载产物。

## 验证状态

- 当前旧工作流 run：`41947919412`，检查时仍在执行，不能据此判断最终成败。

- 优化分支不自动合并 main；待构建验证通过后再审查 PR。

## 1. 项目目标

制作原创美术、卡通斜视伪 2.5D 的竖屏英雄小队 RPG。基础体验以《百炼英雄》为参照：主城整备、摇杆移动、自动战斗、队伍跟随、区域探索、营火/传送、Boss 推图、任务和英雄/装备成长。

产品原则：**先达到参考产品基础体验基线，再验证差异化超越。** 不能以“功能存在”替代同条件的视觉、交互、节奏和性能验收。

核心循环：主城整备 → 野外探索/战斗/采集 → 任务与 Boss 推进 → 区域解锁/营火传送 → 成长与离线回归。

单机边界：不依赖服务器、公会、排行榜、广告/IAP加速；长期深度计划由阵容策略、技能策略、装备 Build、试炼/无尽、图鉴成就和多周目承接。后几项不代表已经实现。

## 5. 痛点与风险

### P0：可玩性证据缺失
- 出口测试只验证坐标半径，不证明角色能沿真实场景道路走到出口。
- 地面轮廓、障碍碰撞、装饰遮挡、出口位置和 Camera2D 投影边界没有联合验收。
- Android 20 项冒烟尚未执行；无设备型号、Android 版本、分辨率/DPI、录像与缺陷记录。
- 当前 HEAD CI 尚未结束，不能报通过。

### P1：地图仍是过渡架构
- 四张独立 map_id 尚未升级为“大区域—子区域—道路节点—门/营火”的统一世界拓扑。
- 路径节点、物理出口、地图标记、营火锚点分散在不同脚本/数据源，存在坐标漂移风险。
- 区域切换和营火传送仍由 Main 串接部分流程，服务边界还可收敛；不能引入第二套状态/存档规则。

### P1：美术和战斗反馈落后于目标
- 英雄完整逐帧动作不齐，部分为静态图加程序化反馈。
- 自动战斗是否具备可读预警、躲避价值、敌人差异和策略深度尚未通过实机验证。
- 缺少同分辨率、同场景、同操作的参考画面对比记录，不能声称像素级对标。

### P1：分支与文档历史状态漂移
- main 与活动分支有分叉风险；历史审计记录过双方独有提交，合并前必须重新 compare。
- 文档含旧 HEAD/旧 CI 快照；每次交接以当前 ref 和 Actions 为准。
- 分支审计中仍有待核查 refs；当前连接没有 branch DELETE 能力，不得声称已清理。

### P2：单机经济和长线内容未验证
- 本地客户端无法彻底防止系统时间篡改或存档编辑。
- 碎片保底、资源产出、装备词条/重铸、觉醒与任务卡点需要模拟和真实进度测试。
- 多存档、试炼/无尽、图鉴成就、多周目不属于当前已交付能力。

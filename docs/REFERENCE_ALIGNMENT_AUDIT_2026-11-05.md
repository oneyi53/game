# 2026-11-05 全仓开发分支对标一致性审计

## 最高开发指引

本文件是本轮全仓分支审计的执行记录。最高开发方向：以《百炼英雄》作为玩法体验硬性对标，只学习体验组织与设计规律，不复制其代码、美术、角色、文案或专有表达。具体验收以 `docs/BAILIAN_HERO_REFERENCE_STUDY.md` 第 13 节为准：

1. 大区域地图探索：连续可走路线、岔路/地形/阻挡/地标/资源/宝箱/营地/传送/敌群/精英/Boss。
2. 镜头空间：平滑跟随、边界夹取、统一投影、深度排序、脚底锚点与碰撞一致。
3. 角色表现：待机/行走/朝向状态、起步减速、脚步反馈、队伍跟随；静态 PNG 不得冒充动画。
4. 探索闭环：迷雾/区域发现、探索度、采集、宝箱、营地、传送、任务事件、区域解锁。
5. 战斗闭环：自动攻击与手动走位、敌人感知/追击/攻击范围、精英/Boss 预警与阶段。
6. 移动端体验：竖屏触控、浮动摇杆、多点触控、GUI 优先、安全区、不同宽高比和帧率验收。

任何 UI、任务、成长、红点、装备、构建子系统都必须服务于上述循环，不得取代核心玩法。

## 其它分支处理原则

- `main` 是唯一正式主线；本轮不直接修改 main 运行时代码。
- 已合并分支是历史来源，不因新方向而回滚已合并功能；不匹配的体验在统一体验分支中按模块替换。
- 文案/系统草稿分支（`content/*`）属于内容候选，不是可直接合并的运行时主线；逐文件审核，禁止复制竞品文案或世界观。
- 纯文档、测试、CI、资源归档分支属于支撑工作；必须服从新的质量与验收标准，但不要求把它们改造成玩法分支。
- 与 main 严重分叉的历史分支不做盲目 rebase、force-push 或删除。通过 compare、文件级审查、cherry-pick/逐文件迁移把有效模块带入统一体验分支。
- 不把“文档写了规则”说成“代码已经改好”；每项运行时调整必须有对应测试/CI 证据，设备体验必须有真机证据。

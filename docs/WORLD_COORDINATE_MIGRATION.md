# 世界坐标与旧存档迁移规范

## 当前事实

- PR #32 的 main 基线仍是旧共享地图：1600×1200；本分支将运行时地图切换到 4 张独立的 1200×900 map-local 地图。
- 旧地图在三个探索区域绘制了明确矩形：苔冠空地 (200,40,1200,280)、落叶幽谷 (40,880,720,280)、朝露林地 (840,880,720,280)。
- 旧存档只保存 `player_position` 的 x/y，没有 `map_id`。
- 历史 2.5D 分支曾定义四张独立地图，但单位边界、存档和屏幕投影不统一；PR #32 按本文件契约重建接入，不直接合并历史分支。

## 本分支的坐标契约

1. 新地图逻辑坐标是地图本地坐标，范围 0..1200 × 0..900。
2. 角色移动、碰撞、攻击距离、出生点和存档都使用逻辑坐标。
3. 2.5D 投影只负责绘制，不允许把投影坐标写回 CharacterBody2D.global_position。
4. Hero、Enemy、Boss 统一调用 `WorldMapManager.clamp_position()`，边距 32；不得各自硬编码旧 20..1580 / 20..1180。
5. 存档位置始终保存为 map-local x/y，并同时保存 `map_id` 与已访问地图的 `map_positions`。

## 旧存档迁移规则

`scripts/core/world_save_migration.gd` 是纯函数迁移层，不直接读写文件；PR #32 已将它接入 Main 的存档加载流程。

- 旧坐标位于苔冠区域：映射为苔冠地图的归一化本地坐标。
- 旧坐标位于落叶区域：仅在精英 Boss 已击败时映射到落叶幽谷（与现行第三地区开放规则一致）。
- 旧坐标位于朝露区域：仅在精英 Boss 击败且第三地区任务完成（存档中的 `quests.completed.side_valley_puppet` 为 true）时映射到朝露林地。
- 锁定区域或未命名区域：安全回退到苔冠空地，不将玩家送进锁定地图。
- 旧坐标映射后统一限制在 32..1168 × 32..868。
- 已有合法 map_id 的新格式存档保留地图，只对位置执行边界校验。
- 无位置的新档使用对应地图出生点。
- 迁移仅新增 `map_id` 与 `map_positions`；金币、木材、背包、装备、招募、任务、英雄血量等字段原样保留；`schema_version` 仍为 1。

## 验证

执行：`godot --headless --path . --script res://tests/test_world_save_migration.gd`。

测试覆盖 13 项：旧坐标映射、地图解锁门槛、新格式存档保留、锁定地图安全回退、缺少位置出生点、四地图边界、敌人地图归属和投影边界。

## 当前运行时接入（PR #32）

- Main 加载存档后先运行纯迁移，再按 `map_id` 生成英雄和敌人；旧存档成功迁移后，在 UI 初始化完成时立即保存新格式。
- `SaveManager.save_game()` 会在主存档有效时先将原文写入 `save_backup.json`；若主存档损坏且从备份恢复，则不会用损坏主存档覆盖备份。
- 新格式保存 `map_id`、`map_positions` 和当前 `player_position`；schema_version 保持 1。
- 地图切换前保存当前地图位置，切换后恢复目标地图上次位置或使用出生点。
- 仍需 Android 真机验证触控、渲染、地图切换和真实旧存档迁移；云端 headless CI 不等于设备验收。

# 世界坐标与旧存档迁移规范

## 当前事实

- 当前 main 的正式逻辑世界仍是共享地图：1600×1200。
- 旧地图在三个探索区域绘制了明确矩形：苔冠空地 (200,40,1200,280)、落叶幽谷 (40,880,720,280)、朝露林地 (840,880,720,280)。
- 旧存档只保存 `player_position` 的 x/y，没有 `map_id`。
- 历史 2.5D 分支定义了四张独立地图，每张地图为 1200×900，并将逻辑坐标、屏幕投影混用在注释和部分边界上；不得直接合并。

## 本分支的坐标契约

1. 新地图逻辑坐标是地图本地坐标，范围 0..1200 × 0..900。
2. 角色移动、碰撞、攻击距离、出生点和存档都使用逻辑坐标。
3. 2.5D 投影只负责绘制，不允许把投影坐标写回 CharacterBody2D.global_position。
4. 所有可移动单位使用统一边界接口，边距 32；不得各自硬编码旧 20..1580 / 20..1180。
5. 存档位置始终保存为 map-local x/y，并同时保存 map_id。

## 旧存档迁移规则

`scripts/core/world_save_migration.gd` 是纯函数迁移层，不直接读写文件。

- 旧坐标位于苔冠区域：映射为苔冠地图的归一化本地坐标。
- 旧坐标位于落叶区域：仅在 Boss 已击败时映射到落叶幽谷。
- 旧坐标位于朝露区域：仅在精英 Boss 击败且第三地区任务完成（存档中的 `quests.completed.side_valley_puppet` 为 true）时映射到朝露林地。
- 锁定区域或未命名区域：安全回退到苔冠空地，不将玩家送进锁定地图。
- 旧坐标映射后统一限制在 32..1168 × 32..868。
- 已有合法 map_id 的新格式存档保留地图，只对位置执行边界校验。
- 无位置的新档使用对应地图出生点。
- 不修改金币、木材、背包、装备、招募、任务、英雄血量等其他存档字段；schema_version 不在此阶段升级。

## 验证

执行：`godot --headless --path . --script res://tests/test_world_save_migration.gd`。

测试覆盖：苔冠映射、已解锁落叶映射、朝露双重解锁门槛、锁定地图回退、未命名旧位置、合法新格式存档保留、锁定的新格式地图安全回退、缺少位置使用出生点（8 项）。

## 接入顺序

先通过本迁移测试，再把它接入主场景加载/保存；之后才接入地图切换和投影。迁移成功后应立即保存一次新格式备份，但不能在迁移失败或存档损坏时覆盖原存档。

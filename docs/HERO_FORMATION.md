# 英雄编队数据层

## 目标

把“已拥有英雄”和“当前出战英雄”分开管理。招募系统仍负责英雄归属、碎片与解锁；编队系统维护出战名单、槽位顺序和队伍上限。

## 当前阶段边界

本阶段只交付纯数据层与回归测试，**尚未接入 Main 的英雄生成、面板交互或存档写入**。因此不会改变当前玩家实际队伍，也不会改变旧存档行为。下一阶段在独立 PR 中接入 UI 和运行时生成。

## 数据契约

存档可选字段：

- `formation.active_ids`：按槽位顺序排列的已拥有英雄 ID 数组；第一个 ID 即当前队长。
- 队伍上限由代码中的 `DEFAULT_MAX_PARTY_SIZE` 配置，当前为 4，不从存档读取。

示例：

```json
{
  "formation": {
    "active_ids": ["archer", "guardian", "healer"]
  }
}
```

## 规则

- 任意已拥有英雄均可担任队长；当前队长由 `active_ids[0]` 决定，不绑定固定英雄 ID。
- 可以将已上阵英雄调到首槽；也可以直接从预备名单提拔为队长。
- 队伍已满时，预备英雄提拔为队长会替换当前首槽英雄，原队长自动进入预备名单。
- 可以下阵任何英雄，包括当前队长；下阵队长后，下一位队员自动成为队长。
- 至少保留一名出战英雄，避免出现无队伍状态。
- 不能上阵未拥有英雄或重复英雄；达到队伍上限后不能继续添加。
- 任意槽位均可交换，交换到首槽即更换队长。
- 存档读取时过滤未知/重复/未拥有 ID；若过滤后没有有效成员，则以第一名已拥有英雄作为初始队长。
- 默认上限为 4，是 Hero World 当前阶段的原创平衡参数，不引用对标截图中的 10 人队伍。

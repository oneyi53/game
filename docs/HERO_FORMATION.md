# 英雄编队数据层

## 目标

把“已拥有英雄”和“当前出战英雄”分开管理。招募系统仍负责英雄归属、碎片与解锁；编队系统只维护出战名单、槽位顺序和队伍上限。

## 当前阶段边界

本阶段只交付纯数据层与回归测试，**尚未接入 Main 的英雄生成、面板交互或存档写入**。因此不会改变当前玩家实际队伍，也不会改变旧存档行为。下一阶段在独立 PR 中接入 UI 和运行时生成。

## 数据契约

存档可选字段：

- `formation.active_ids`：按槽位顺序排列的已拥有英雄 ID 数组；第一个必须是 `captain`。
- 队伍上限由代码中的 `DEFAULT_MAX_PARTY_SIZE` 配置，当前为 4，不从存档读取。

示例：

```json
{
  "formation": {
    "active_ids": ["captain", "archer", "guardian", "healer"]
  }
}
```

## 规则

- 队长必须已拥有、必须上阵，并固定在第 1 槽。
- 不能上阵未拥有英雄或重复英雄。
- 达到队伍上限后不能继续添加。
- 只能移除非队长英雄。
- 只能交换第 2 槽及之后的成员，队长槽位不可移动。
- 存档读取时过滤未知/重复/未拥有 ID；无有效队伍时保留队长。
- 默认上限先定为 4，是 Hero World 当前阶段的原创平衡参数，不引用对标截图中的 10 人队伍。

## 下一阶段

1. 将 RecruitmentManager 的拥有列表传入 FormationManager。
2. Main 只生成 active_ids 对应英雄；英雄收藏/招募仍显示全部 owned_ids。
3. 装备、等级和英雄详情面板支持收藏英雄（包括暂不上阵的英雄）。
4. 上阵、下阵、换位成功后保存 formation 字段，并刷新队伍与面板。
5. 验证旧存档首次迁移、招募后可上阵、退队后仍保留装备/等级/碎片，以及 MAX_UNITS 约束。

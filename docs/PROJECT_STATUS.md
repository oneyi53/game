## 1. 项目定位

Hero World 是原创单机 RPG，目标平台为 Android，目标体验为竖屏移动端、卡通斜视伪 2.5D 世界。核心玩法方向包括英雄小队探索、自动战斗、装备成长、营地建设、地图/区域探索与离线本地存档。

**视觉方向已确定：A——卡通斜视伪 2.5D。** 这属于目标方向，不代表当前主线已经实现。

## 3. 当前主线已有的模块与资源

- `scenes/`：主场景、英雄、普通敌人、Boss、营火、宝箱。
- `scripts/core/`：主流程、地图绘制、数据加载、本地存档。
- `scripts/character/`、`scripts/enemy/`、`scripts/interactable/`：英雄、敌人/Boss、交互物。
- `scripts/progression/`：背包、营地、装备、等级、离线收益、任务、招募管理。
- `scripts/ui/`：HUD、摇杆及英雄/装备/背包/营地/离线/招募面板。
- `data/`：英雄、敌人、任务、装备、掉落、等级、招募、营地等 JSON。
- `assets/art-v1/`：基础英雄、怪物、Boss、装备、场景图集与单体 PNG。

main 已包含基础美术资源，但资源存在不等于运行时已经显示。资源归属和 2.5D 分支差异见 `BRANCH_AUDIT.md`；主线本地运行时引用初审见 `LOCAL_CODE_AUDIT_2026-11-04.md`。

## 4. 当前已知风险与待核查项

### 来自 2.5D / 美术分支审查

1. 地图尺寸不一致：WorldProjection、WorldMapManager、MapDrawer 使用 1200×900，但 Hero/Enemy/Boss 仍 clamp 到 1600×1200。
2. 旧存档位置迁移未完成：旧版共享地图坐标可能被直接载入新独立地图。
3. 竖屏视口下投影地图的占屏比例需要 Godot 实际画面验证。
4. 地图装饰可能没有按地图切换独立集合。
5. 静态贴图已接入分支但完整行走/攻击动画未做。
6. 美术说明文档存在过期描述。

### 来自 main 本地第一轮静态审查

以下均为待复核线索，不应未经调用链验证就认定为确定缺陷：

1. `MAX_UNITS` 总量限制可能压缩满编队伍下的怪物刷新容量，存在任务目标刷新阻塞风险。
2. 招募碎片合成可能缺少碎片扣除。
3. 英雄 HP 可能保存但未在读档生成时正确恢复。
4. UI 多个面板可能同时显示，缺少互斥管理。
5. mailbox 可能没有容量上限。
6. 树木/地标可能只有绘制、没有碰撞阻挡。
7. 面板刷新时销毁并重建控件可能带来分配开销，但需要实际性能测量。
8. Chest 的 Area2D 碰撞可能未用于实际交互检测。
9. 离线收益依赖本地系统时间，属于单机可修改时间的设计限制。

详细证据方向和逐项验证清单见 `LOCAL_CODE_AUDIT_2026-11-04.md`。

## 5. 建议的整合与修复顺序

1. 先完成核心逻辑交叉审查：怪物刷新、招募碎片、英雄 HP、任务奖励、存档恢复。
2. 再确定地图坐标契约、实体边界接口、多地图结构和旧存档迁移方案。
3. 然后复用现有 PNG 接入静态美术，再安排动画。
4. 补齐营火传送、营地建筑、散件装备和任务交付闭环。
5. 最后集中验证竖屏镜头、触控 UI、移动端性能和 Android/iOS 构建。

不直接合并整个旧 2.5D/美术分支；逐文件迁移，保留 main 中较新的玩法和存档实现。

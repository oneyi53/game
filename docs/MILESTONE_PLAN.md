# Hero World M0-M2 里程碑执行计划

> 生效日期：2026-11-05。执行分支：`feat/reference-grade-world-exploration-2026-11-05`。
> 原则：冻结新系统；以“主城出发—野外战斗—采集—回城—养成—再次出发”作为唯一核心验收路径。
> 重要边界：本计划的时间是目标排期，不是完成承诺。每个出口必须有真实 Android 设备证据；CI/headless/代码提交不能替代真机验收。

## 阶段定位

当前判断为“系统骨架已存在，垂直切片闭环尚未取得真机验收”。已有地图/传送、队伍、战斗、资源采集首版、营地、装备、招募、任务、离线存档等模块，但存在代码已接入≠体验完整的问题。当前六名英雄是静态单图；程序化缩放/位移反馈不等于五类逐帧动画。采集首版为即时完成，尚无“采集中”过程态。

## 冻结规则（M0-M2）

暂停开发：天赋树、宠物、成就、PVP、公会、排行榜、新货币、专武/觉醒/符文/宝石等养成纵轴、商业化功能、UI框架重构。联机与付费系统永久不纳入本项目。只有直接阻断 M0-M2 验收的修复/基础设施可以插队。

## M0：垂直切片闭环（目标 3 周）

目标路径：冷启动主城 → 进入户外区域 → 手动移动/遭遇敌人 → 完成战斗 → 采集资源 → 营火传送/回城 → 升级英雄或更换装备 → 再次出发。

|---|---|---|---:|---|

**M0 出口**：指定 feature SHA 的 APK、设备型号/系统/分辨率、完整流程录像、20 项冒烟结果、问题清单。未通过不启动 M1。

## M1：第一章可玩（目标 4 周）

范围控制为 2-3 个区域、1 个章节 Boss、1 条任务链、1 名新英雄确定性解锁，目标 2-3 小时内容。完成任务接取/追踪/奖励闭环、Boss 阶段机制、至少 3 套可获取装备、可跳过的新手提示、旧存档迁移测试。英雄解锁优先使用任务固定碎片奖励；若确需随机掉落，必须实现并测试 N≤20 的保底。外部非开发者完成试玩后再决定是否进入 M2。

## M2：内容扩展基线（目标 4 周）

建立区域配置、敌人行为模块、击杀/采集/护送/对话/到达任务节点模板；制作第二章（1 区域、1 精英、1 Boss）验证管线；完成内容生产 SOP 和性能回归。只有 M2 出口达标后才评估新系统。

## 质量门禁

- 分支：继续在本开发分支完成垂直切片；不直接推 main；每个可独立交付任务尽量控制在 5 天内。
- 合并：CI 绿灯、代码自审、变更对应的自动化测试；核心闭环必须另有 Android 真机验收证据。
- CI 目标：JSON 配置字段/类型/引用校验；主城/战斗/各面板场景 smoke；旧存档 fixture 迁移断言；APK 包名/版本/体积/指定 SHA 校验。
- 每周：周一排期、周三构建自测、周五可演示构建；每两周评审一次里程碑。
- 缺陷级别：S0 卡死/黑屏/存档丢失/核心路径阻断，立即修复；S1 动画/数值/UI遮挡，当前里程碑修复；S2 表现瑕疵排后续；S3 建议进入 backlog。

## 风险登记

| 风险 | 应对 |
|---|---|
| 动画图集未到位 | 先以程序化占位完成状态反馈；真实逐帧动画需原创素材，不能把占位标成动画验收 |
| 真机性能不达标 | M0 中段提前测；减少同屏单位/特效或锁 30fps，并记录依据 |
| 第一章内容超期 | 收缩为 2 区域+1 Boss+1 任务链；新英雄改任务固定奖励 |
| 存档迁移丢失 | 使用旧档副本和 fixtures；每次候选构建前执行迁移测试 |
| 范围蔓延 | 冻结清单置顶；新想法写入 backlog，M2 后评估 |
| 长期无可演示版本 | 每两周固定产出候选 APK；构建失败也记录原因，不用旧包冒充新 SHA |

## 本轮代码审计发现（静态）

- 资源点由 Main 动态创建，稳定 ID、地图 ID、耗尽列表均进入存档；木材满时不会消耗资源点。
- 采集是一次点击立即完成，当前没有“采集中”动画/进度/打断状态；与 M0-4 三态验收不符。
- HUD 只有木材数量和通用交互按钮提示，尚未明确显示“可采集/采集中/已耗尽”三态。
- 队长怒气由成功调用敌人 `take_damage` 后增加；技能消耗 3 怒气，按 140 世界单位范围造成双倍攻击伤害。该规则需要运行回归，不视为已平衡。
- 英雄动作仍为单张 PNG 上的程序化形变/闪烁/后坐，不是逐帧 idle/walk/attack/hit/death。
- 以上均为静态代码观察；未执行 Godot、Android 导出或真机测试。

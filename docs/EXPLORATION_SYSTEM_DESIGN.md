日期：2026-11-05

## 1. 目标体验

玩家从安全营地出发，在连续野外地图中移动、遭遇敌人、采集资源、发现地标和传送阵；探索过程逐步揭开迷雾并累积区域探索度。地图界面应能查看当前区域、怪物/地标和已发现的传送目的地。回城整理队伍后可再次出发。

## 2. 当前实现基线（静态代码审查）

### 已存在
- `WorldMapManager` 定义 town、moss_crown、fallen_leaf、morning_dew 四个独立地图 ID，逻辑地图尺寸 1600×1400，坐标为 map-local。
- `WorldProjection` 负责逻辑世界到竖屏等距投影，投影不应改变存档坐标。
- `ExplorationFog` 使用 80 世界单位网格，半径 260 世界单位揭示；非主城绘制未探索单元格，并可导出已探索 cell key。
- `Main` 已将各地图的探索 cell 数组写入 `explored_map_cells` 存档字典；读取时过滤未知地图 ID。
- 传送目的地、区域门槛和任务系统已有基础实现。

### 明确缺口
- E1 已完成：Fog 提供有效格数、总格数、比例和整数百分比 API；过滤非法/重复/越界 cell，主城返回不适用。7 项首轮回归已在 Godot 4.7.2 CI #630 通过；本轮扩展至 8 项，新增主城不适用状态回归，等待最新 CI。\n- E2 首轮已接入：HUD 在野外区域名下显示“探索度 X%”；新揭示格后刷新，切换地图后加载目标地图统计；主城隐藏该标签。当前等待 CI 验证，720×1280 实机排版仍待截图验收。
- 迷雾揭示仅依据角色位置，尚无传送阵/任务/地图交互对探索状态的统一事件契约。
- 小地图完整闭环（当前区域定位、怪物与地标标记、锁定目的地、传送后位置同步）仍未由本设计验证。
- 区域解锁当前与 Boss/任务状态耦合；需要避免击败 Boss 后无提示自动切图替代玩家自主探索。
- 视觉雾格与等距投影需用实际运行截图检查边缘、遮挡和地图边界，不以代码静态审查代替画面验收。

## 3. 数据与坐标契约

1. **唯一权威坐标**：所有角色、怪物、资源点、传送点和探索格使用 map-local 逻辑坐标（0..1600, 0..1400）。
2. **渲染投影隔离**：UI 标记、迷雾多边形和地图图标在绘制时统一调用 WorldProjection；禁止各系统重复实现投影公式。
3. **地图状态隔离**：探索数据按 map_id 分桶；切图时先保存当前地图状态，再加载目标地图状态；不同地图的探索格绝不混用。
4. **稳定 ID**：怪物、资源点、地标、传送点均使用配置稳定 ID；存档不使用场景节点路径或屏幕坐标。
5. **未知数据安全**：未知 map_id、无效 cell key、越界坐标和重复 ID 必须被拒绝或安全忽略；不能破坏已有有效存档。

## 4. 探索度计算规范

当前地图尺寸 1600×1400，网格 CELL_SIZE=80：
- 列数：ceil(1600/80)=20
- 行数：ceil(1400/80)=18
- 理论网格总数：360
- 探索度：有效且位于地图范围内的已探索格数 / 360 × 100，显示整数百分比。
- 边缘最后一行实际高度为 40；仍按一个格计数，避免边缘格被重复加权。
- 同一格重复揭示只能计数一次。
- 主城不显示迷雾探索度（显示“安全区域”或不显示百分比）。
- 进度必须单调不减；切换地图时显示该地图自己的进度。

后续如地图尺寸或 cell size 变化，分母必须由地图 bounds 与 cell size 动态计算，不能硬编码 360。

## 5. 事件与系统边界

- `ExplorationFog`：只负责网格揭示、有效 cell 集合、探索度计算与迷雾渲染；不直接操作 HUD、任务、存档文件或地图切换。
- `Main`：负责玩家位置更新、调用 reveal、按既有节流机制持久化；切图时切换 map state。
- `WorldMapManager`：负责地图元数据、解锁判定、出生点和安全区标记；不负责 UI。
- `MapPanel`（后续）：读取只读地图快照，显示当前区域、探索度、已发现传送点、怪物/地标标记；发出传送请求，不直接修改队伍节点。
- `TeleportService`（后续可从 Main 拆分）：统一验证解锁、目的地合法性、队伍坐标、镜头、敌人/资源状态、存档更新；避免多个 UI 入口各自实现切图。
- 任务系统只接收明确的 explore/map_enter 等领域事件，不通过读取 UI 文本判断任务进度。

### E2：HUD 探索反馈
- [ ] 野外显示当前区域名与探索百分比。

- [ ] 主城不显示误导性的 0%。
- [ ] 720×1280、1080×1920 等竖屏布局不遮挡操作区。

### E3：小地图与传送
- [ ] 打开地图默认定位当前区域与玩家位置。
- [ ] 仅显示已发现/符合可见规则的怪物、地标和传送点。
- [ ] 未解锁目的地清晰显示条件，点击再次做服务端式本地校验。
- [ ] 成功传送同步队伍、镜头、当前地图、探索状态并保存；失败不产生半切图状态。
- [ ] 传送过程不丢失其他地图探索记录。

### E4：区域推进与任务
- [ ] Boss 击败只更新击败状态和任务目标，不自动夺走玩家控制权切图。
- [ ] 新区域通过任务/探索门槛开放，并给出明确提示与可选前往入口。
- [ ] 营地回城、重新出发、旧存档恢复均可重复完成。

### E5：视觉与真机验收

- [ ] 录制移动揭雾、查看地图、传送、回城再出发的完整流程。
- [ ] 记录 APK commit、设备、Android 版本、分辨率、帧率和缺陷。
- [ ] 自动化测试通过不能代替真机验收。

## 7. 风险与决策
- 网格揭雾属于探索体验简化；未来如需更自然边缘，可在不改变 cell 存档契约的前提下增加渲染遮罩/边缘平滑层。
- 当前参考公开视频并非全部可在此环境逐帧下载解码；没有观察到的 UI 细节标记为待采样，不凭空补全。
- 本规格不复制原游戏图标、角色、场景、字体或特效；所有正式素材必须为项目原创或明确授权资源。
